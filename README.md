# Rattonero Books

A small, native reader for EPUB and PDF. A Rust core does everything that is
not user interface; a SwiftUI app for macOS and iOS sits on top of it. Other
front ends (GTK4, Plasma, Windows) can reuse the core unchanged.

## Layout

| Path | What |
| --- | --- |
| `core/` | `rattonero-core` (Rust): library scan, metadata, shelf ordering, EPUB parsing, sanitising, pagination script and stylesheet, reading positions |
| `apple/` | SwiftUI app (`Rattonero/`), its XcodeGen spec, and the icon artwork (`icon-source/`) |
| `tools/` | `xtask` (the build system), UniFFI binding generator, sample-book generator |

## Build

One command builds everything, on every platform:

```sh
cargo xtask build            # add --release for optimised, universal builds
```

It tests the core, builds it, and builds every front end the machine can
build. On a Mac that means the core for macOS, iOS and the iOS simulator, the
Swift bindings, `apple/RattoneroCore.xcframework`, the Xcode project, and
both apps (in `target/xcode/Build/Products/`). On Linux and Windows it builds
and tests the core today; new front ends add their steps to
`tools/xtask/src/main.rs`.

Needs Rust everywhere. On a Mac also Xcode,
[XcodeGen](https://github.com/yonaskolb/XcodeGen) and the Rust targets
`aarch64-apple-darwin`, `aarch64-apple-ios`, `aarch64-apple-ios-sim`
(plus `x86_64-apple-darwin` for `--release`).

`cargo xtask test` runs only the core's tests. To run or debug the apps, open
`apple/Rattonero.xcodeproj` after a build. `tools/make-samples.py <folder>`
writes a few made-up books to try things out.

## How it fits together

* **Bookshelf.** `Library::scan` walks the chosen folder (read-only) for
  `.epub` and `.pdf`, reads metadata with a cache, and `arrange` orders the
  books by author, title, publisher or year the way a library would: surnames
  first, leading articles ignored, accents folded.
* **Reading EPUBs.** `EpubBook::resource(path)` returns any file of the book;
  chapters come back sanitised and wrapped for paged layout. The front end
  shows them in a web view through a custom URL scheme (`rattonero-book://`)
  and injects `reader_script()`, which paginates with CSS columns, turns
  pages, and reports taps, links, image taps and text selection. The message
  protocol is documented at the top of `core/src/reader.js`.
* **Reading PDFs.** The core supplies metadata and remembers the page; the
  platform renders (PDFKit on Apple systems).

## Safety

Book files are untrusted input.

* All parsing is safe Rust, with size caps on everything read from an archive.
* Chapter markup is rebuilt from an allow-list: no scripts, event handlers,
  forms, frames or objects; only stylesheets survive from the head.
* Every chapter carries a Content-Security-Policy that allows nothing but the
  book's own resources. The Apple app also disables JavaScript for content,
  installs a content blocker for all other URLs, refuses navigations it did
  not start, and uses a non-persistent web data store.
* The Mac app is sandboxed with read-only access to the folder you pick.

## Porting to another toolkit

A front end needs: a folder picker; a grid for `arrange()`'s shelves; a web
view with a custom scheme handler answering from `EpubBook::resource`, the
`reader_script()` injected as a user script, and a message channel named
`rattonero`; and a PDF widget. A GTK4 front end in Rust can depend on
`rattonero-core` directly; others use the UniFFI bindings (Kotlin, Python,
C#, ...) generated by `tools/uniffi-bindgen`.
